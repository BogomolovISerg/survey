# Изменения в ERPServer1 для анкетирования v2

Часть изменений уже внесена в проект EDT через MCP-плагин (см. «Статус»); остальное — исходники здесь, для переноса.

## Состав

| Объект | Что | Статус |
|---|---|---|
| `Catalog.бигМероприятия` | реквизиты `Опубликовано` (Дата/время), `ВерсияПубликации` (Число 5), `ПубличнаяСсылка` (Строка 500), `КурсорВыгрузки` (Число 15), `ЗагруженоАнкет` (Число 10) | внесены в EDT плагином |
| `CommonModule.бигАнкетированиеОбменСервер` | серверный общий модуль (Сервер, ВызовСервера, ВнешнееСоединение), в подсистеме `бигАнкетирование` | объект создан в EDT; текст модуля — `CommonModules/бигАнкетированиеОбменСервер/Module.bsl` |
| `Catalog.бигМероприятия` → `ФормаЭлемента` | группа «Сервис анкетирования»: поля Опубликовано, ВерсияПубликации, ПубличнаяСсылка, ЗагруженоАнкет, КурсорВыгрузки (только чтение); кнопки **Опубликовать в сервисе**, **Загрузить результаты**, **Открыть анкету** | обработчики — `Catalogs/бигМероприятия/Forms/ФормаЭлемента/Module.additions.bsl` |
| `ScheduledJob.бигЗагрузкаРезультатовАнкетирования` | метод `бигАнкетированиеОбменСервер.ЗагрузитьРезультатыВсехМероприятий`, расписание каждые 15 минут, предопределённое, выключено по умолчанию | создать в EDT (или включить в мониторе регламентных заданий после обновления) |
| Роли | `бигДобавлениеИзменениеДанныхАнкет`/роль маркетинга: доступ к новым реквизитам не требует отдельных прав; кнопки вызывают серверный модуль под правами пользователя — запись реквизитов идёт в привилегированном режиме | — |
| Настройки | безопасное хранилище, владелец `"survey"`: `url`, `login`, `password` | задать один раз (см. ниже) |

## Настройка обмена

В консоли кода / обработке (под администратором):
```bsl
бигАнкетированиеОбменСервер.УстановитьНастройкиОбмена("https://survey.bigcom.ru/survey", "erp", "пароль_учётки_INTEGRATION");
```
Учётка `erp` создаётся в админке сервиса (`/survey/admin/users`, роль INTEGRATION). Проверка: `бигАнкетированиеОбменСервер.НастройкиОбмена()`.

## Как это работает

1. **Опубликовать в сервисе** — форма записывает объект, модуль берёт `Справочники.бигКомпонентыАнкеты.СформироватьJSON(Анкета)`
   и шлёт `PUT /api/v1/sync/events/{GUID}`; в реквизиты пишутся `Опубликовано`, `ВерсияПубликации`, `ПубличнаяСсылка` (для QR).
   Повторная публикация без изменений анкеты версию не создаёт. Изменили анкету — опубликуйте ещё раз.
2. **Загрузить результаты** — постранично `GET …/responses?after=КурсорВыгрузки`, каждая пачка пишется в РС `бигДанныеАнкет`
   в одной транзакции (`Дата`=submittedAt, `Идентификатор`=id ответа, `Данные`=структура ответов как в v1, `ДанныеJSON`,
   `БонусПредоставлен`), затем курсор сохраняется и подтверждается `ack`. Повторный приход того же id (изменился подарок)
   обновляет ту же строку — дублей нет. Отчёт `бигРезультатыОпроса` работает без изменений.
3. Регламентное задание вызывает `ЗагрузитьРезультатыВсехМероприятий()` — по опубликованным мероприятиям, дата окончания
   которых не раньше 7 дней назад.

## Форма элемента — что добавить (если делать руками)

Группа `ГруппаСервисАнкетирования` (обычная, заголовок «Сервис анкетирования») после поля `Подарок`:
- поля: `Объект.Опубликовано`, `Объект.ВерсияПубликации`, `Объект.ПубличнаяСсылка` (ТолькоПросмотр), `Объект.ЗагруженоАнкет`, `Объект.КурсорВыгрузки` (ТолькоПросмотр);
- командная панель с кнопками `ОпубликоватьВСервисе` («Опубликовать в сервисе»), `ЗагрузитьРезультаты` («Загрузить результаты»), `ОткрытьАнкету` («Открыть анкету»);
- обработчики — из `Module.additions.bsl`.
